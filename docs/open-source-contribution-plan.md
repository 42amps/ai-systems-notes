# Open Source Contribution Plan

Goal: build a visible, useful contribution trail without fake activity or noisy drive-by PRs.

## Target Repo Categories

- AI agent frameworks.
- RAG and document AI tools.
- Developer tools.
- Django or FastAPI examples.
- React and TypeScript UI libraries.
- Docs-heavy open-source projects.

## How To Choose Issues

Good issues are small, reproducible, and useful:

- Broken setup instructions.
- Missing example for a documented feature.
- Broken links.
- Type errors in examples.
- Tests that need a small regression case.
- Docs that are confusing after following them locally.

## What Counts As A Good PR

A good PR makes the project easier to use or maintain:

- Clear problem statement.
- Small diff.
- Reproduction notes.
- Before/after behavior.
- Tests or docs where appropriate.
- Respect for project style.

## What Not To Do

- Do not open cosmetic PRs just to appear active.
- Do not rewrite maintainers' docs without a concrete reason.
- Do not claim expertise the PR does not show.
- Do not open broad refactors as a first contribution.
- Do not spam multiple repos with the same change.

## 30-Day Target

Target: 5 useful external PRs in 30 days.

Preferred PR types:

- Docs improvements.
- Examples.
- Tests.
- Small bugfixes.
- Reproduction notes.
- Setup fixes.
